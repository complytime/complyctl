## Why

The complyctl RPM spec file has not been updated since the v0.0.8 era and
diverges from current Fedora Go packaging guidelines in three ways:
debuginfo generation is explicitly disabled, vendored dependency licensing
is not machine-verified, and the build does not use standard Fedora Go
macros. With v1.0.0 already released upstream, the spec must be brought
into alignment so Koji builds succeed cleanly and the package passes
Fedora review requirements.

## What Changes

- **Fix debuginfo generation**: Remove `%global debug_package %{nil}` and
  switch from manual `go build` to the `%gobuild` macro, which injects
  build-id, DWARF preservation, external linkmode, and hardened linker
  flags automatically.
- **Adopt go-vendor-tools**: Add `Source1` (vendor archive generated by
  `go_vendor_archive create`), `Source2` (`go-vendor-tools.toml` config),
  and integrate `%go_vendor_license_buildrequires`,
  `%go_vendor_license_install`, `%go_vendor_license_check`, and
  `%{go_vendor_license_filelist}` macros for automated license scanning
  of vendored dependencies.
- **Modernize spec structure**: Use `%gobuild` with `GO_LDFLAGS` for
  version injection, `%gocheck2` for unit tests (excluding integration
  and E2E tests), `%autorelease` for automatic release numbering, and
  `ExclusiveArch: %{go_arches}` via `%gometa -f`.
- **Update Packit integration**: Add `srpm_build_deps` for Copr SRPM
  builds, `post-modifications` action for vendor archive generation,
  sync `go-vendor-tools.toml` to dist-git, and set
  `create_sync_note: false`.
- **Retain Fedora 43 compatibility**: Keep the conditional `go.mod` and
  `vendor/modules.txt` sed hack for Go 1.25 on F43 (EOL 2026-12-09).
- **Align version to 1.0.0**: Set `Version:` tag to match the current
  upstream release. The version is operationally coupled to the vendor
  archive naming (`complyctl-1.0.0-vendor.tar.bz2`). Note that the
  `Version:` tag in the upstream spec serves as a default; Packit
  overrides it from the release tag during `propose_downstream`.

## Capabilities

### New Capabilities

None. This change modifies packaging infrastructure only; no application
behavior changes.

### Modified Capabilities

None. Pure packaging/tooling change (`skip_specs: true`).

### Removed Capabilities

None.

## Constitution Alignment

- **I. Single Source of Truth**: PASS -- `go-vendor-tools.toml`
  centralizes vendor license config; version ldflags use `GO_LDFLAGS`
  env var instead of inline strings.
- **II. Simplicity & Isolation**: PASS -- Replacing manual build logic
  with single macro calls (`%gobuild`, `%gocheck2`).
- **III. Incremental Improvement**: PASS -- Focused on packaging only;
  no application code changes.
- **V. Do Not Reinvent the Wheel**: PASS -- Adopts standard Fedora Go
  macros (`%gobuild`, `%gocheck2`, `%autorelease`) and go-vendor-tools
  instead of manual reimplementations.
- **VII. Convention Over Configuration**: PASS -- Aligns with Fedora Go
  packaging conventions; `%autorelease` eliminates manual release
  numbering.

## Impact

- **Files modified**: `complyctl.spec`, `.packit.yaml`
- **Files created**: `go-vendor-tools.toml`
- **Build dependencies**: Adds `go-vendor-tools` as `BuildRequires` and
  Packit `srpm_build_deps` entry
- **CI/CD**: Copr builds will generate vendor archives via
  `post-modifications`; `propose_downstream` will use the same action
  to generate archives for Fedora dist-git
- **CentOS Stream**: CentOS Stream Copr build targets removed
  temporarily because `go-vendor-tools` is not available in CentOS
  Stream repos. Can be restored when the tooling becomes available
  there -- see design.md D9.
- **Release process**: No changes to GitHub release workflow; vendor
  archive generation is handled downstream by Packit
- **Fedora dist-git**: PR #5 (go-vendor-tools adoption) will be
  superseded by a new PR generated via `propose_downstream` after
  this lands
